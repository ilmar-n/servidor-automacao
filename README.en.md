# Automation server: n8n + Postgres with off-site backup

[Versão em português](README.md)

A production setup of [n8n](https://n8n.io) on a VPS. It has a Postgres database, HTTPS and secrets kept out of the code. Every day it makes an **encrypted, off-site backup, and restoring from it has been tested**. This is the setup I offer to small businesses.

**Live:** https://n8n.ilmartec.com.br (the public page shows only the login screen).

## The problem
Many n8n installs are a single `docker run` with SQLite and no backup, and the encryption key ends up lost somewhere. That works until a disk fails or an upgrade goes wrong. Then the workflows and credentials are gone.

This setup is built for that day:
- the data can be recovered from a backup kept off the server;
- the restore procedure is written down and has been tested;
- nothing but the reverse proxy is exposed to the internet.

## What's included
- **n8n 2.46.6 + Postgres 16** on Docker Compose, with pinned versions.
- **Task runners in external mode:** code from *Code* nodes (JS and Python) runs in a separate container.
- **HTTPS** through nginx + Let's Encrypt (Certbot), with WebSocket support for the editor.
- **Daily backup at 03:30 (São Paulo time)** with restic → Cloudflare R2:
  - Postgres dump + `data/n8n` + `.env`;
  - encrypted;
  - keeps 7 daily, 4 weekly and 6 monthly snapshots;
  - integrity check every Sunday.
- **Secrets generated by a script**, with mode 600, kept out of Git.

## Architecture

```
Internet ──HTTPS──▶ nginx (80/443, Let's Encrypt certificate)
                      │  reverse proxy (WebSocket enabled)
                      ▼
               127.0.0.1:5678   ← n8n's only port, local only
┌──────────────── Docker Compose internal network ────────────────┐
│  n8n ─────────────▶ postgres   (data in data/postgres)           │
│   ▲                                                              │
│   └── runners → n8n:5679   (broker; runs Code node code,         │
│                             no published port)                   │
└──────────────────────────────────────────────────────────────────┘

systemd timer 03:30 ─▶ scripts/backup.sh
   pg_dump + data/n8n + .env ─▶ restic (encrypts) ─▶ Cloudflare R2
```

## Design decisions
| Decision | Why |
|---|---|
| Postgres, not SQLite | Sturdier for continuous use, and `pg_dump` gives a consistent dump without stopping the service |
| External task runners | Workflow code runs outside the main n8n process. This is the mode the [official docs](https://docs.n8n.io/deploy/host-n8n/configure-n8n/set-up-task-runners) recommend for production |
| n8n bound to `127.0.0.1` | Nothing reaches n8n without going through the HTTPS proxy |
| Back up the dump, not the Postgres folder | Copying the data folder while the database runs can produce an inconsistent copy |
| `.env` included in the backup | Without `N8N_ENCRYPTION_KEY`, the credentials saved in n8n can't be decrypted after a restore. restic encrypts everything, and its password lives only in the password manager |
| R2 token scoped to one bucket | If the server is compromised, the token gives no access to other buckets in the account |
| Pinned versions | An upgrade is a decision, made after a backup, not a surprise from a `pull` |
| First access restricted by IP | In n8n, whoever opens the page first becomes the instance owner. nginx allows only the installer's IP until the owner account exists |

## Installation
Requirements: Linux with Docker Engine + Compose v2, nginx, Certbot, restic and openssl, plus a domain with an `A` record pointing to the machine. Tested on an ARM64 VPS (Oracle Cloud) running Ubuntu; the images also exist for amd64.

```bash
git clone https://github.com/ilmar-n/servidor-automacao.git
cd servidor-automacao

# 1. Secrets: creates .env with random passwords and prepares data/
scripts/gerar-env.sh n8n.yourdomain.com
#    → copy the contents of .env to your password manager NOW

# 2. Start the containers
docker compose up -d
docker compose ps
curl -s http://127.0.0.1:5678/healthz      # {"status":"ok"}

# 3. nginx + HTTPS (the template starts open only to your IP)
sudo cp deploy/nginx/n8n.conf.example /etc/nginx/sites-available/n8n.conf
sudo sed -i -e "s/N8N_HOST/n8n.yourdomain.com/" -e "s/SEU_IP/<your public IP>/" \
     /etc/nginx/sites-available/n8n.conf
sudo ln -s /etc/nginx/sites-available/n8n.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d n8n.yourdomain.com

# 4. Open https://n8n.yourdomain.com and create the owner account.
#    Then delete the allow/deny lines from n8n.conf:
sudo nginx -t && sudo systemctl reload nginx
```

After creating the owner, turn on two-factor authentication in *Settings → Profile & preferences → Enable 2FA* and keep the recovery codes in your password manager. This is free. What requires a paid plan is **enforcing** 2FA for all users (*Settings → Policies*).

### Backup
```bash
# Asks for the R2 Account ID, access key and secret (typed on the machine,
# never stored in a versioned file). Generates the restic password and shows
# it ONCE: save it in your password manager.
scripts/configurar-backup.sh
sudo scripts/backup.sh init        # creates the restic repository in the bucket
sudo scripts/backup.sh             # first backup

# Daily schedule
sudo cp deploy/systemd/backup-n8n.service deploy/systemd/backup-n8n.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now backup-n8n.timer
```

**Adjust before installing:**
- the path `/home/ubuntu/servidor-automacao` in `deploy/systemd/backup-n8n.service`;
- the bucket name (`BUCKET` in `configurar-backup.sh`);
- the `--host` used in `backup.sh`.

The backup runs as root because `data/n8n` is owned by uid 1000, the n8n container user.

## Restore
To restore, you need three things:
- this repository;
- the **restic password**, from the password manager;
- an R2 token with access to the bucket.

```bash
# New machine with Docker and restic. Do NOT run gerar-env.sh: .env comes from the backup.
git clone https://github.com/ilmar-n/servidor-automacao.git
cd servidor-automacao

# 1. Create .env.backup by hand (mode 600) with the SAME restic password.
#    The template is in scripts/configurar-backup.sh. The script itself
#    generates a new password, so it can't be used for a restore.

# 2. List the snapshots and restore the latest one into the project folder
#    (restic puts .env, data/n8n and backups/n8n.dump back in place)
sudo bash -c 'set -a; source .env.backup; restic snapshots && restic restore latest --target .'
sudo chown "$USER": .env && chmod 600 .env
sudo chown -R 1000:1000 data/n8n

# 3. Start only Postgres and load the dump
docker compose up -d postgres
docker compose cp backups/n8n.dump postgres:/tmp/n8n.dump
docker compose exec postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner /tmp/n8n.dump'

# 4. Start everything else and check
docker compose up -d
curl -s http://127.0.0.1:5678/healthz
```

**Test on 2026-11-09:**
- The snapshot was restored, and `.env` and `data/n8n` came back identical to production.
- The dump was loaded into a throwaway Postgres 16 and matched production: 173 tables and the same row counts.

The full procedure on a clean VM, with the time measured, is the next test (see "Limitations").

## Operations
| Task | Command |
|---|---|
| Container status | `docker compose ps` |
| n8n logs | `docker compose logs -f n8n` |
| Manual backup | `sudo systemctl start backup-n8n` |
| Backup log | `journalctl -u backup-n8n` |
| List snapshots | `sudo bash -c 'set -a; source .env.backup; restic snapshots'` |
| Upgrade n8n | 1. manual backup · 2. change `N8N_VERSION` in `.env` (n8n and runners share it) · 3. `docker compose pull && docker compose up -d` · 4. `healthz` |

## Limitations and next steps
These parts are **not** done yet:
- **Monitoring and alerts:** if a backup fails or the site goes down, nobody is notified. Next step: Uptime Kuma.
- **Restore on a clean VM**, with the time measured.
- **A single machine, with no high availability.** The recovery plan is the backup.
- **Operating system hardening** (key-only SSH, firewall, automatic updates) is outside the scope of this repository.
- **A version for servers without a public IP**, behind Cloudflare Tunnel: planned.
